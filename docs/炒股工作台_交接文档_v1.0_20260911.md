# 炒股工作台（帽子哥板块评分）交接文档 v1.0

> 日期：2026-09-11　|　依据：《帽子哥技能画像 v2.0》《SKILL 定义 v2.0》
> 目的：把帽子哥的六层思维架构编译成一套**可每日自动更新、手机端秒开、评分可解释可留痕**的板块决策工作台

---

## 1. 需求全景

**原始需求**
- 借鉴帽子哥技能画像与思维方式，把其分析框架融入系统
- 每日自动接收新闻、自动更新股市数据
- 结合新闻与各行业板块动态做**板块量化评分**，作为买卖决策依据
- 须先调研现有工作台优缺点，再给出改进设计
- 交付物：功能模块、数据来源、评分逻辑、自动化机制、实现方案与代码

**追加需求 1**：用户可自选关注的行业板块；进入板块看该板块新闻 + 该板块量化评分；数据源必须免费；落地为手机端网页，适配移动端、加载流畅；明确实现范围 / 每日更新方式 / 评分维度 / 展示方式。

**追加需求 2**：不使用服务器；更新方式为"每次打开网页自动更新"。

**追加需求 3**：对比 A（纯前端直连）与 B（静态站点+免费定时构建）后确定——使用一个免费账号（采用 B 骨架）；**评分时间改为每个交易日下午 14:00**；评分维度回到 **10–12 维**。

**追加需求 4（最终确认）**
1. 申请 tushare token（用于真实行业估值）
2. 托管平台最终选 **GitHub Pages**
3. 自选板块上限确认为 **12 个**
4. 负面清单（白酒/地产/整车/钢铁特钢/游戏影视/商业航天）**可手动修改**
5. 无需微信推送

## 2. 已锁定的关键决策

| 项 | 决策 | 说明 |
|---|---|---|
| 架构 | **B 骨架 + A 实时补丁（混合）** | 历史/评分/新闻/解禁全部预计算；打开时用 1 个 JSONP 请求补当日实时快照 |

| 免责 | 不构成投资建议；免费接口仅供个人研究 | 页面固定展示 |

## 3. 目标架构

```
GitHub Actions（免费定时执行环境，无需运维）
  13:40 预热 → 抓历史K线/估值/解禁/新闻（不依赖当日收盘）
  14:00 主评分 → 抓当日盘中快照 → 12维计算 → 生成JSON → 提交发布
  15:30 收盘复核 → 用收盘价重算归档（回测与事后复核基准）
        ↓ 提交产物
GitHub Pages（静态托管）
        ↓ 手机打开
纯前端 PWA：读JSON秒开 → 1个JSONP请求补实时 → 本地微调分数 → 刷新UI
```

**为什么必须混合**：14:00 属盘中，GitHub Actions 的 cron 有 5–30 分钟延迟，不能作为盘中决策的唯一时间源；前端实时补丁保证了"你此刻打开，看到的就是此刻的市场"。

## 5. 评分引擎规格

### 5.1 十二维权重（11 正向，合计 100%）

| # | 维度 | 权重 | 计算要点 | 数据源 |
|---|---|---|---|---|
| 1 | 动量 | 10% | 5/20/60 日涨幅加权 + 相对沪深300 超额 | 板块K线 |
| 2 | 趋势结构 | 10% | MA20/MA60 位置、多头排列、KDJ(9,3,3) 金叉与 J 值 | 板块K线 |
| 3 | 量价健康 | 8% | 调整期缩量比、上涨放量比、量价背离 | 板块K线 |
| 4 | 换手率位置 | 8% | 板块换手率 250 日分位（低位加分、高位扣分） | 板块K线 |
| 5 | 主力资金流 | 10% | 主力净流入占比 | 资金流排名 |
| 6 | 估值位置 | 10% | 行业 PE/PB 历史分位；无 token 用 252 日价格分位（标注"代理"） | tushare / 价格 |
| 7 | 周期位置 | 8% | 库存周期阶段 + 涨价信号（商品价或"提价/缺货"关键词） | 商品/新闻 |
| 8 | 行业出清度 | 6% | 出清链条阶段（煤炭→家电→手机→汽车→AI）；已出清转股息加分 | **人工维护静态表** |
| 9 | 政策强度 | 6% | 官方媒体政策关键词命中（反内卷/供给侧/稳增长） | 新闻 |
| 10 | 新闻情绪 | 12% | 情绪分 × 时效衰减 × 板块相关度，近 3 日累加 | 新闻 |
| 11 | 板块共振 | 12% | 成分股涨跌一致性 + 龙头与跟随同步（三好学生三维共振） | 成分股 |
| 12 | 筹码供给（负向） | 罚分 0–20 | 未来 30 日解禁市值/流通市值 + 近期减持公告数 | 解禁/减持 |

### 5.2 计算公式

```
f_i  = 因子按滚动 250 日窗口做分位归一化 → [0,1]
S_base = 100 × Σ(w_i × f_i)                       # Σw = 1
P_supply = min(20, 12×解禁压力归一 + 4×减持久归一)
P_blacklist = 命中负面清单 → 分数上限压至 45 并打「回避」标记
S = clamp(S_base − P_supply − P_blacklist, 0, 100)
```

### 5.3 分级与动作

| 分数 | 标签 | 动作 |
|---|---|---|
| ≥75 | 主升共振 | 逢低吸：48 次补仓法网格分批，单次 5% |
| 60–75 | 进入观察 | 小仓试探，跌破预设支撑才加 |
| 45–60 | 中性 | 卧倒 |
| 30–45 | 转弱 | 逢高减：分批累计 30% |
| <30 | 回避 | 空仓，等解禁出清后的"黄金坑" |

### 5.4 宏观分 M 与决策矩阵（关键）

宏观分 M 由**股市上涨四要素**构成：流动性 30% / 量价关系 25% / 政策 25% / 情绪 20%。
**情绪项做逆向映射**（对应帽子哥"散户情绪极差＝无关变量，甚至反向指标"）。

| 板块分 S ↓ / 宏观分 M → | M≥70 进攻 | 40≤M<70 中性 | M<40 防守 |
|---|---|---|---|
| ≥75 | 按网格分批建仓 | 小仓试探（≤半仓） | 只观察不动手 |
| 60–75 | 观察，跌破支撑再加 | 观察 | 观察 |
| 30–45 | 逢高减 30% | 逢高减 | 逢高减（加速） |
| <30 | 回避 | 回避 | 回避 |

**设计意图**：板块分决定"买什么/卖什么"，宏观分决定"能用多少仓位"——对应帽子哥"仓位第一"与"宏观决定配置"。

### 5.5 附加纪律提示（页面固定输出）
单次 5%、累计 30%/50%；不到预设点位不做 T；换手率回到 3% 以上触发减仓提示；科技↔红利相对强弱给出跷跷板方向；不承诺收益、不推荐个股代码。

## 6. 每日自动化流程（北京时间）

| 时点 | 任务 | cron (UTC) |
|---|---|---|
| 13:40 | 预热：抓历史K线增量、解禁、新闻 | `40 5 * * 1-5` |
| **14:00** | **主评分：抓盘中快照 → 12 维 → 发布** | `0 6 * * 1-5` |
| 15:30 | 收盘复核：用收盘价重算并归档 | `30 7 * * 1-5` |
| 手动 | `workflow_dispatch` 随时补跑 | — |

> ⚠️ **本节是 v1.0 时期的设计记录，已不是当前实现**：现行调度为「**12 次/日**」
> （09:10 预热 + 09:35–15:05 每 30 分钟评分 + 15:35 收盘归档），且时间戳统一走
> `pipeline/clock.py`（CI runner 是 UTC，不能直接用 `datetime.now()`）。
> **以 [炒股工作台_交接文档_v2.2_20260916.md](炒股工作台_交接文档_v2.2_20260916.md) 的 §3.2 / §3.3 为准。**

**盘中数据特殊处理**：盘中各次评分的当日 K 线为未完成 bar，产物中标注 `intraday: true`
（15:35 收盘复核时自动转为 `false`）。

## 7. 前端规格（移动端）

- **首屏**：吸顶横向 chips 切换自选板块 → 评分环（总分+分级+动作+数据时间戳）→ 12 维横向条形 → 新闻流（**利好红 / 利空绿**）→ 底部纪律条
- **实时补丁**：打开时 1 个 JSONP 请求拉全部板块快照 → 本地微调 → 分数滚动到最新
- **缓存**：自选与配置存 localStorage；快照 TTL 3 分钟；下拉刷新 = 跳过 TTL
- **性能**：首屏无框架依赖；骨架屏；PWA（manifest + Service Worker，可加桌面、离线看缓存）；暗色模式；safe-area；触控目标 ≥44px
- **容错**：JSONP 超时 8s → 回退缓存

**验证结果**（合成数据，仅验证代码正确性，不代表真实策略表现）：
- 宏观四要素：缺失数据全部回退 0.5；情绪逆向映射生效（亢奋 61.8 < 低迷 71.8）
- 筹码：解禁 500 亿 / 市值 2 万亿 = 2.5% → 罚分 7.6（修正了此前的**双重归一化缺陷**）
- 回测：1 日 IC 0.298 / ICIR 1.958 / 多空胜率 94%；IC 随持有期自然衰减（20 日降至 0.092）；各期分层单调
