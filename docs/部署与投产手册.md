## 二、投产路线（推荐直接走 A）

项目已支持「CI 自举」：`sector_meta.json` 会自动生成，因此**不要求你的本机能连东财**。

| | 路线 A：直接推 GitHub（推荐） | 路线 B：先本地跑通 |
|---|---|---|
| 适用 | 本机网络受限（内网/代理拦截东财） | 本机能直连东财 |
| 步骤 | 建仓库 → 推代码 → 手动触发一次 | 本地装依赖 → 跑 warmup/score → 再推 |
| 优点 | 一次搞定，CI 出口网络通常可连东财 | 能在本地看到中间过程，便于调试 |

> 若你不确定本机能否连东财，先用一行命令自测：
> ```bash
> curl -s -m 10 "https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=1&fs=m:90+t:2&fields=f12,f14"
> ```
> 有 JSON 返回 → 可走 B；超时或报错 → 走 A。

### Step 1–2　仓库初始化与推送　✅ 已完成（2026-09-15）

- 仓库：`https://github.com/chuanwudi46-ops/Big-A`（**Public**，Pages 免费账户要求）
- 提交：2 个，共 **26 个文件**（纯源码，未含合成数据与 K 线缓存）
- 提交作者：`chuanwudi46-ops <chuanwudi46-ops@users.noreply.github.com>`
- remote：`https://github.com/chuanwudi46-ops/Big-A.git`（URL 中**不含**任何 token）

> **本机未安装独立 Git**（`C:\Program Files\Git` 不存在）。此环境用的是 WorkBuddy
> 自带的 PortableGit，其默认凭据组件 `helper-selector` 在非交互场景下无法弹窗，
> 直接 `git push` 会报 `could not read Username`。
>
> **解决办法**：显式指定 Git Credential Manager（PortableGit 自带，版本 2.9.0）——
> ```bash
> git -c credential.helper=manager push -u origin main
> ```
> 会弹出 GitHub 登录窗口，授权一次后凭据被 Windows 凭据管理器缓存，
> 之后普通 `git push` 即可直接生效。

### Step 3　开启 Pages 与配置 Secret

在仓库 **Settings** 里操作：

| 位置 | 操作 |
|---|---|
| `Settings → Pages → Source` | 选 **GitHub Actions**（不要选 "Deploy from a branch"） |

## 五、必须纠正的一点：tushare 拿不到行业估值

原交接文档写的「估值维度用 tushare `index_dailybasic` 取行业 PE/PB」**是行不通的**，已实测核对官方权限表：

| 事实 | 详情 |
|---|---|
| 积分门槛 | `index_dailybasic` 需 **4000 积分起**（免费注册仅 120 分；充值 1 元 = 10 分，即约需 400 元） |
| 覆盖范围 | 官方文档明确「**目前只提供**上证综指、深证成指、上证50、中证500、中小板指、创业板指」——**不含任何行业** |
| 结论 | 即使充值到 4000 分，也**拿不到行业 PE/PB**；原方案此路不通 |

**因此估值维度有三个可选口径：**

| 口径 | 成本 | 说明 |
|---|---|---|
| **A. 价格分位代理**（当前默认） | 0 | 用 252 日价格分位代表"贵/便宜"。系统已实现，产物标注 `price_proxy`。**建议先这样投产** |
| B. akshare 免费行业估值 | 0 | akshare 存在行业市盈率接口（巨潮资讯行业市盈率、中证行业指数估值等），可拿到申万一级/证监会大类的平均 PE。**代价**：需把约 31 个申万行业与 86 个东财板块做映射表，映射不准会误判 |
| C. tushare `daily_basic` 聚合 | 约 200 元 | 2000 积分，用个股每日 PE/PB 按板块成分股聚合出中位数。口径最准，但需付费 + 额外开发 |

> **建议**：先按 A 投产跑起来，等真实数据积累后再决定要不要升级到 B（免费，性价比最高）。

**每月建议**：看一眼 `docs/backtest_report.md`（重跑 `python pipeline/backtest.py`），确认 IC 没走坏。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| Actions 报 `ModuleNotFoundError` | 依赖未装全 | 检查 `pipeline/requirements.txt`，CI 已自动 `pip install` |
| 日志大量 `[warn] hist xxx` | 东财限流或网络拦截 | 正常降级，不影响其他板块；若 86 个全失败则检查出口网络 |
| `scored 0 boards` | K 线缓存为空（warmup 未成功） | 先单独跑 `stage=warmup`，确认成功再跑 score |
| Pages 打开 404 | Pages Source 未设为 GitHub Actions | 回 Step 3 |
| 数据不更新 | Workflow permissions 无写权限 | 回 Step 3，提交步骤会静默失败 |
| 手机显示「用 T-1 数据」 | 当日构建失败，前端读了缓存 | 看 Actions 日志定位；必要时手动触发 |
| 页面白屏 | 接口变更 / SW 缓存了旧版 | 硬刷新；`sw.js` 每次发版改 `C = "wb-v2"` |
| 界面还是假数据 | 未跑真实 score，或产物未提交 | 检查 `meta.json` 有无 `demo: true` |
